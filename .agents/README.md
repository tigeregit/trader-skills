# .agents/ — agent 协作文档库

本目录是 agent 协作过程中的**长期维护文档库**，与项目交付物（`skills/`）、参考源（`ref/`）分离。一切「过程性、知识性、待办性」的内容归此管理。

> 项目顶层约定见仓库根 `AGENTS.md`。本文件是 `.agents/` 的总入口与维护规范。

## 目录职责

| 目录 | 放什么 | 不放什么 |
|------|--------|---------|
| `notes/` | **知识方法总结**：已确立、长期有效的方法/规范/设计（如测试方法、架构设计） | 未成型的草稿、一次性调研 |
| `todo/` | **待办**：尚未完成、可独立认领交付的事项（每个 .md 一项） | 已完成的事项（完成后删除，见下）、正式产物 |
| `temp/` | **临时**：草稿、调研笔记、一次性分析、中间产物 | 长期有效的结论（应晋升到 notes） |

## 内容流转

内容随成熟度在三个目录间流动，避免临时内容污染正式文档、避免已完成项堆积：

```
temp/（草稿/调研） ──成熟──► notes/（方法/规范）
                       │
                       └──拆解──► todo/（落地为可执行事项）

todo/（完成） ──产物──► skills/ 或 notes/（正式位置）
            └──TODO 文件删除──► todo/README 清单移除
```

- **temp → notes**：调研/草稿沉淀为稳定结论后，整理迁入 `notes/`，temp 原文件删除。
- **notes → todo**：一个方法/设计需要落地实现时，在 `todo/` 拆成可执行事项，`todo/` 文件「来源」指向 `notes/` 对应文档。
- **todo → 产物**：待办完成后，产物落到 `skills/`（代码）或 `notes/`（文档），**TODO 文件本身删除**并在 `todo/README.md` 清单移除。`todo/` 只保留未完成项。

## 维护规则

1. **入口权威**：本文件管 `.agents/` 全局；`todo/README.md` 只管 `todo/` 内部清单与状态。两者分层，不重复。
2. **命名**：所有文件 kebab-case、语义化（如 `gateway-mvp.md`、`test-method.md`）。
3. **temp 定期清理**：`temp/` 不堆积历史，晋升到 notes/todo 或废弃后即删除。
4. **引用规范**：跨目录引用用相对路径（如 `notes/test-method.md`），便于检索与移动。
5. **新增子目录**：默认只用上述三个；如需新增（如 `decisions/` ADR），先在本文件登记职责。
